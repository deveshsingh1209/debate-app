# Architecture

A single-user program that runs on your own machine. You describe a decision; a panel of AI experts argues it in motions until each is ruled on; you get a report. Debates are long (an hour or more), so the design is built around surviving restarts and browser disconnects.

## Requirements

**Functional:** live multi-agent debate with genuinely separate agent minds; user gates (goal, panel, plan) with revise loops; mid-debate questions to the user; an autonomous mode; uploaded context files; a depth profile (chosen automatically for hard calls) that shapes the process, never a default spend limit; an interactive report and PDF; live streaming of speeches; a library of past debates.

**Non-functional:** one user, one machine. Debates must survive process restarts and browser disconnects. Quality over cost: spend is shown, never used to shorten a debate unless the user set their own ceiling; a spent model quota pauses and resumes. Credentials stay with the user's own CLIs and environment.

**Non-requirements:** multi-tenancy, horizontal scale, high availability.

## Shape

```
Browser (Vite React SPA)
   │ http://127.0.0.1:8794   (Host / Origin / CSRF guards; optional password)
   ┌──────────────────────────────────────────────┐
   │ ONE Node process (Fastify)                   │
   │  REST + SSE hub (replay from seq)            │
   │  Engine: DebateRun state machine per debate  │──► Claude CLI subprocesses (Agent SDK)
   │    Marcus ─ experts ─ lint ─ referee ─ ...   │──► OpenAI Responses API (HTTPS)
   │  Spend meter (information) + waste guards    │──► Codex CLI subprocesses (Codex SDK)
   │  Report renderer (pure function)             │     (≤ MAX_AGENTS at once)
   │  Notifier (optional, off by default)         │──► api.telegram.org sendMessage only
   └───────┬──────────────────────────────────────┘
     SQLite (WAL): debates + append-only events
     data/debates/<id>/: context/, work/, transcript.md, agents.md, report.html, report.pdf
```

**The load-bearing idea:** the append-only event log is the single source of truth. The UI is a fold over events (`GET /api/debates/:id` plus SSE replay from `seq`); each agent's prompt is a slice of the same log; the report is a reduction of it; `transcript.md` is a readable projection. One history, four consumers.

## Models and providers

`shared/models.ts` is the only file that names a model. The user picks one of four provider doors for each debate (Claude sign-in `claude`, Claude API key `anthropic`, ChatGPT through Codex `codex`, OpenAI API key `openai`) and the product casts every seat to that door's tier for the job:

| Tier | Seats | Claude (sign-in and API key) | OpenAI / Codex |
|---|---|---|---|
| flagship | chair (Marcus), expert floor turns, rulings, referee, report, quant desk and audits, summoning an expert | `claude-opus-5-5` | `gpt-6-astra` |
| balanced | research, dossier reading, the experts' dossiers and the relationships pass (`persona`), report copy-fitting | `claude-sonnet-5-5` | `gpt-6.1-sol` |
| fast | turn rewrites (lint), listener reactions (`react`, one call per set piece or contested reply), the clerk (starting stances from the position cards, research findings against cruxes; OpenAI research's findings step) | `claude-haiku-4-5` | `gpt-6-luna` |

A debate stays on one provider from start to finish. `agents/sdk.ts` binds each debate to its provider and dispatches every turn: the Claude path spawns the Claude CLI through the Agent SDK (both Claude doors; the API key door differs only in the child's environment, see Credentials); `agents/openai.ts` streams from the Responses API; `agents/codex.ts` drives the Codex CLI. Web research works on every door through one interface and one citation schema (`research/`): the Claude CLI's WebSearch (the desk then fetches the cited pages itself, extracts at most 4,000 characters each and has a fresh tool-free turn check the findings against them), OpenAI's `web_search` tool capped by `max_tool_calls`, or a Codex research thread with its own search switched on (every other Codex turn keeps it off). Every research call is metered step by step (`research/meter.ts`): a `[research:tokens]` log line per call, a search allowance and token tripwires enforced on the Claude door by a PreToolUse hook, and a stated budget of 80,000 tokens per call that `research/cost.selftest.ts` holds it to. The envelope counts what research adds over each session's fixed baseline (calibrated on its first request, which never stops a session); the baseline is logged beside it and priced in `docs/ENVELOPE-REPORT.md`. No agent loads an MCP server of the user's (`strictMcpConfig`, claude.ai connectors off). An identical question in the same debate is answered once. The architect's web pass runs behind the same search allowance. Only the Claude path has file tools and python, so OpenAI and Codex sessions skip the quant desk and say so in the room.

## Deep dives

**Event log and streaming.** Persisted events carry a monotonic per-debate `seq`. Token deltas are ephemeral live frames; the finished `message` event supersedes them. A partial-message buffer replays an in-progress speech to a browser that connects mid-speech, so a refresh is lossless. A restart loses only the in-flight turn, which re-runs.

**Meeting loop.** One driver loop per debate (`DebateRun.drive` in `engine/runner.ts`); phases are statuses (`intake` through `complete`, plus `paused`, `error`, `cancelled`); every point where the engine waits for the user is re-derivable from the database, which is what makes resume after restart honest. Each motion runs on the **live floor** (`engine/floor.ts`, since 2b-7) in checkpoints of six to eight written turns (`engine/motions.ts`). After each checkpoint the referee judges whether genuinely new argument appeared. Each profile states its own length (`length` in `shared/budget.ts`, since P2): a round target, a round cap, messages per motion and per session (shared between the motions still open, closings and an adversary round reserved), so the director is asked only for the turns that fit and stops at the checkpoint's message budget. On Quick and Standard, past the target, a referee that says the crux is settled or one checkpoint with no new substance (circling, exhausted or nothing new) closes the motion; at the cap or the message budget it is ruled with the reason `budget`. Deep keeps the old rule (two dry checkpoints, or a referee that says it is ready, after the target) and the old backstops. The motion then winds down (anyone the crux turns on who has not been heard gets one short turn) and Marcus writes a ruling. The adversary desk (seats per depth profile) then attacks the ruling. A motion also closes, as a recorded stalemate, when several turns in a row only repeat the room. Faults degrade rather than stop (a failed lint rewrite ships the turn as written, a failed reaction call means nobody reacts, a failed referee is a no-verdict checkpoint, a failed check-in leaves the room to the director); a spent allowance is not a fault and never degrades anything: it pauses the debate (below).

**Founder pause (P4).** Pause works at every step until the report is done. `meta.founderPause` holds the step Resume goes back to; a step already running finishes its in-flight call and its next status is recorded there instead of entered (`setStatus`), and the driver waits on a resume gate rather than on a user signal. In the meeting the motion checkpoint records where the motion stands (`open` checkpoint with the turns it still owes, `closing`, `ruling`, the adversary's `challenge`, `redTeamed`), so a pause never rules, closes or advances a motion: a turn being written is dropped unheard, a turn already written and planned plays first on Resume with no new model call, and the adversary round resumes with the turns it still owes. Wrap-up stops between closings and the report between the audit, the writer, its adversary and the correction (`meta.reportProgress`). End while paused cancels before the meeting and goes to the closings after it.

**The live floor.** The floor director (`engine/director.ts`, pure and seeded) picks who speaks and the turn's shape and length: a set piece (the speaker's own natural length) when someone has a case to make, a reply (25-45 words) when they were put on the spot, owe an answer or are in a duel, and short reactions. Each turn is **written in full first**, then one fast `react` call reads every listener's reaction off it sentence by sentence; the director, not the model, decides whether anyone cuts in (heat plus intensity against the listener's threshold, never before the first sentence, never the founder, capped per motion by profile), who wins the floor fight, and whether a listener says something short afterwards. Only then is the turn **performed** at speaking pace (`SPEAKING_PACE`, 2.5 words a second): the cut-in streams over the speaker's last words, the silence after it is a `pause` event, a speaker who wins the floor back restarts the cut sentence, and every `message` carries only the words heard. The unsaid remainder lives only in the motion checkpoint while the turn plays, so a restart mid-performance plays it again without a new model call. While turn k plays, turn k+1 is written against a projection of exactly what k's audience will have heard. Marcus is a light facilitator: a check-in at each checkpoint (a nudge to one person, research, the desk, the agenda, a question for the founder) and otherwise a line only on a trigger (a dodge pressed twice, heat with a cooldown, the belief ledger's herd or unexplained fold, clock milestones). Research that lands goes straight to the expert whose crux it hits. Heat rises when someone is addressed, cut off or provoked, and decays by temperament; seats carry air-time weights (dominance, conviction) so the floor is uneven, and the relevance rule means nobody the crux turns on is left silent.

**Dossiers, stakes and the belief ledger (2b-5).** After the architect, each expert gets a dossier on the balanced `persona` seat (history, personal incentives, register, natural length, habits, stubbornness, temperament); a deterministic diversity check (`realism/dossier.ts`) redrafts offenders once, and a panel that still fails goes ahead flagged at panel approval. Only each expert's public reputation joins the cached roster; the private voice card rides in their own suffix. Intake reads the stakes; missing fields are stated, conservative assumptions, marked assumed in the cached STAKES block and the report. Every STANCE line goes through the belief ledger (`realism/ledger.ts`): a move becomes a `concession` event with what moved it and what it cost, the referee is asked to attribute unexplained moves, and herds, drift and unexplained folds by stubborn experts become chair triggers. Rulings name the stakes' decision owner and both costs of being wrong, and every dissent carries a tripwire. The report adds what was at stake, how minds changed and the dissent record, all server-written.

**Agents.** Experts are stateless voices over one shared, cached room record: every seat in a round presents the same system prompt, and identity (persona, private position card, turn shape) rides in a small per-turn suffix. Each expert turn ends with a hidden trailer (stance, graded claims, a direct question, a desk call) that is stripped before anyone reads it; its claims pass a deterministic evidence check (`realism/evidence.ts`: `observed` only when traceable to the founder's brief, answers or uploads or to a cited research id, a panelist's own backstory is `persona`, never evidence), then the turn passes a rules linter; a memo-like turn is rewritten on the fast tier and kept only if code verifies nothing of substance moved. `settingSources: []` keeps your own CLAUDE.md out of every persona. Experts hold no tools; research has web search only (pages are read by the server's own guarded fetcher, `research/pages.ts`), and no seat that reads upload-derived text holds web tools (the panel architect is a web pass on topic and goal plus a tool-free designer that reads the dossier); research questions pass a gate (no links, addresses or encoded strings) and the architect web pass's WebFetch opens only pages a search in the same debate returned, never a private address (PreToolUse and PostToolUse hooks in `agents/sdk.ts`); the dossier analyst's file tools are scoped to the upload folder; the quant desk's python runs in the OS sandbox with no network, and every tool-holding seat is denied reads of credential locations. Uploaded text, and everything derived from it or from the web (the dossier brief, research, quant output), reaches models only inside content-hashed `<<<UNTRUSTED>>>` fences.

**Budget: quality over cost.** Every number lives in `shared/budget.ts`. Nothing in it is a default spend limit.
- *Depth profiles* (`quick`, `standard`, `deep`) describe process: maximum experts and motions, minimum rounds per motion, adversary seats on rulings and on the report, per-seat thinking, and research runaway guards (per session and per motion). `auto` (the default) resolves at intake (`pickProfile` in `server/src/budget.ts`): the intake's own `exhaustive` depth read, more decisions or disciplines than standard seats, or high-stakes words in the brief send the session to `deep`; otherwise `standard`; never `quick`. The pick is persisted in `meta.profilePick`; the founder can override it until the panel is designed (`POST /api/debates/:id/profile`). `server/src/scope.ts` sizes the session inside the profile and prices an informational estimate ("typically about $X-Y; no limit is applied").
- *The meter* (`budgetSnapshot`) is information only: spend vs the estimate, a projection, and whether the dollars are plan-equivalent (Claude), real pay-per-use money (OpenAI, shown prominently) or none (Codex). Nothing reads it to decide anything.
- *The optional ceiling* (`DebateConfig.ceilingUsd` or `BUDGET_CEILING_USD`, off by default) is checked between checkpoints. At it the room asks the founder to extend (one click raises it by half, at least $5) or to stop; stopping is the ordinary End, so every open motion is ruled and the closings and report still run.
- *Waste guards.* At the dispatch point in `agents/sdk.ts`, `agents/waste.ts` shares an identical call already in flight and refuses an identical call that has already succeeded twice (a loop); retries and JSON repairs are bounded from the config. In the motion engine, `engine/novelty.ts` measures each spoken turn's share of never-said-before word trigrams; `staleTurnsToClose` repeating turns in a row close the motion as a stalemate (the ruling is told the room got stuck, not done). `DEPTH.maxRoundsPerMotion`, `maxMessagesPerMotion` and `hardMessageCeiling` in `shared/types.ts` remain as runaway backstops for debates from before profiles; profiled debates use their profile's `length`.
- *Quota pauses.* The first usage-limit error on a debate latches it (`LimitLatch` in `agents/sdk.ts`): later calls fail fast, the catches on the floor, referee, steer, ruling, adversary and report paths rethrow it instead of degrading, and the driver checks it before every step and every round, so it parks the debate as `paused` instead of arguing on a dead line. `meta.limitPause` records the step it interrupted and the next try (the stated reset, a Retry-After, or a backoff from 5 minutes doubling to a 1-hour cap); a persisted `quota` event tells the room when it resumes; a restart re-arms the timer; after 8 days it gives up as a credential problem. There is no quota-window meter because the Claude SDK exposes none.
- Debates with no `profile` (from before profiles) run exactly as before. Debates from the capped era keep their profile and run without caps; their old `budget` events still render.

**Concurrency.** `MAX_AGENTS` (default 4) agent turns run at once. One slot is never taken by the critical path and research is held to two slots, so background research cannot starve the meeting (Claude CLI path; OpenAI and Codex keep their own limiters).

**The MOCK engine.** `MOCK=1` runs this same engine with scripted models (`engine/mock-live.ts`, built from the mock-v2 scenarios) behind the `wireAgents` seam, so a mock debate exercises the live floor, the ledger and the report end to end with no model call. `MOCK_ENGINE=scripted` keeps the older fixed player.

**Access.** Local by default: bound to 127.0.0.1, a Host allowlist against DNS rebinding, an Origin check (scheme, host and port) on every request, and a CSRF token on every state change. Setting `ACCESS_PASSWORD` adds in-memory cookie sessions; it is mandatory when `HOST` is not loopback (the Docker image generates one into the data volume when none is set). See `SECURITY.md`.

**Credentials.** None stored. Claude: your Claude Code login (the CLI finds it through `HOME`). Claude API key: `ANTHROPIC_API_KEY`, read at start-up, removed from the process environment, and set only in the environment of the Claude CLI child of a debate on that door (with `CLAUDE_CODE_OAUTH_TOKEN` withheld from it, so it cannot fall back to the subscription); the Claude CLI's error text is redacted before it is logged or shown. OpenAI: `OPENAI_API_KEY`, read once at start-up. Both keys are re-read from `.env` when the user presses Re-check, so adding one needs no restart. Codex: your `codex login`, re-read before each turn, with any token rotation written back so your own CLI stays signed in.

**Readiness of the doors.** `server/src/doors/probe.ts` decides, with no model call, whether each door is `ready`, `needs_setup` or `problem`, with the fix in plain words: `claude auth status` (or `CLAUDE_CODE_OAUTH_TOKEN`), the API keys' presence and shape (plus an installed Claude CLI for the key door), and the Codex `auth.json` with `codex login status` to explain a missing one. The result carries no key, token, account name or raw CLI output. `GET /api/doors` serves it from a 30 s cache (`?fresh=1` re-checks); the Connect screen, the New Debate gate, `POST /api/debates` and `npm run doctor` all read the same probe.

**Storage.** SQLite in WAL mode with a single synchronous writer, which is right for one process. A snapshot is taken at start-up and daily into `data/backups/` (last seven kept). `npm run import-backup` brings debates from an older data directory.

## Trade-offs

| Decision | Cost | Why it is right here |
|---|---|---|
| One process (engine in the web server) | a restart kills in-flight turns | resume makes it a hiccup; a queue would be complexity with no payoff for one user |
| Event sourcing without a transactional status/event write | theoretical skew on a crash mid-transition | the next boot re-derives from status |
| Stateless experts over a shared cached prefix | no private memory beyond the record and the card | one cache write per round instead of one per persona per turn |
| No default spend limit; guards target waste | a hard call can cost several times the estimate | a cut debate is a worse decision, which costs more than the tokens; the user can still set their own ceiling, and it asks rather than cuts |
| In-memory sessions | a restart signs you out | nothing to store, nothing to leak |
| SQLite over a server database | one writer | there is exactly one writer |
| Fixed seat casting | no per-debate model tuning | predictable cost and quality; one line to change in models.ts |

## Tests

`npm run qa` runs offline: the report renderer, prompt fences, the OpenAI and Codex client self-tests, the floor director and the live floor (replay, projection, restart mid-performance, chair triggers, wind-down), the budget (meter, auto pick, ceiling, quota schedule, waste guards, repetition check), a real `DebateRun` (including an expensive session that is not cut, a ceiling extended then stopped, a stalemate, a quota pause resumed, dossiers and the diversity redraft, causes on belief changes, overlap events, unsaid words never reaching a prompt, a restart mid-performance, and an old row running unchanged) driven from intake to `complete` through a fake agent seam (`wireAgents` in `agents/sdk.ts`), session length per profile replayed from the 2026-10-28 real run's referee and a founder pause at every phase (`engine/flow.selftest.ts`), the MOCK live path on both scenarios, the web reducer (`web/src/lib/debate-state.ts`) and the transcript metrics. `npm run security-test` attacks a live server in three configurations.

## Revisit when

- **Debates beyond ~500 speeches:** add periodic summarisation checkpoints instead of ever-growing session resumes.
- **Very large uploads or non-text media:** staged ingestion with per-file summaries.
- **Cost surprises:** recalibrate the per-seat cost bands (`TURN_COST` in `shared/budget.ts`) from `meta.spendByRole` of real sessions on the current models.
